# 用户中心运营（uc-ops）Implementation Plan

> **For Claude:** Implement task-by-task. Scheme A: SSO is the only formal login.

**Goal:** 新增 `@ctp/uc-ops`（端口 3005）：面向 C 端注册用户的运营后台；运营人员仅通过 SSO 开通账号并进入。

**Architecture:** uc-ops 无正式登录页。未带 SSO ticket / 无会话时跳转 SSO；SSO 首页入口与登录回跳携带 ticket。应用内 mock「UC 管理 API」数据（用户、入驻关系、登录日志、操作审计）。

**Tech Stack:** Vite + React 19 + React Router 7 + `@ctp/styles`（`theme-customer` 白色侧栏）

---

## 标准菜单与模块

| 菜单 | 模块 | 管理什么 |
|---|---|---|
| 工作台 | Dashboard | 注册量、冻结数、今日登录、待关注风险 |
| 用户管理 → 全部用户 | 用户列表/详情 | 账号身份、状态、资料、入驻关系 |
| 安全中心 → 登录日志 | 登录审计 | C 端登录成功/失败 |
| 安全中心 → 风险事件 | 风控 | 异常登录、频繁失败等（演示） |
| 系统 → 操作日志 | 运营审计 | 运营在本系统的冻结/解冻等操作 |

## C 端用户数据与行为（v1）

**数据：** uid、用户名、手机、邮箱、状态(正常/冻结/注销)、注册时间/渠道、最近登录、实名状态、各控制台入驻状态  
**行为：** 查看列表/详情、冻结、解冻（不做开户——开户在门户/UC 自助）

## SSO 集成（方案 A）

1. 子系统 `sys-uc-ops`，entryUrl `http://localhost:3005`
2. 角色 `uc_ops_admin` / `uc_ops_viewer`，admin 绑定
3. Launcher 打开入口时附带 `sso_ticket` + 用户信息
4. Login 支持 `return_url`，登录后带 ticket 回跳 uc-ops

## Tasks

1. Scaffold `apps/uc-ops`
2. Auth gate + pages + stores
3. SSO subsystem/roles/launcher/login
4. Root scripts `dev:uc-ops` / `build:uc-ops`
5. Typecheck

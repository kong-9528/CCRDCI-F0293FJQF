# DCI® 技术服务中心 — 业务架构图 · 文生图提示词

> 用途：粘贴到文生图 / 架构图生成模型（或人工制图说明）。  
> 依据：仓库 `apps/portal`、`apps/customer`、`apps/ops` 与共享包 `packages/*` 的业务职责（前端原型边界已注明）。  
> 使用建议：优先用「主提示词」整段生成；若模型吃不下长文，改用「精简版」；需要分层出图时按「分镜提示」逐张生成再拼接。

---

## 主提示词（推荐整段使用）

```text
请生成一张「企业级 B2B SaaS 业务架构图」，中文标签，横向或略横向的分层信息架构，适合放到产品说明书或技术方案里。

【画风与版式硬性要求】
- 白底或极浅灰底；扁平、线框卡片；无渐变、无霓虹、无玻璃拟态、无 emoji、无 3D、无人物插画
- 清晰分层（自上而下 4～5 层），层与层之间用细箭头连接；同层系统并排
- 每个系统用圆角矩形卡片，标题加粗，卡片内用短列表写 3～6 条能力（小字）
- 主色：深蓝/石板灰结构线 + 少量强调色区分「三端应用」；共享包用更浅的底色
- 图标题写在顶部：「DCI® 技术服务中心 · 业务架构」
- 图注写在底部小字：「前端原型架构示意；业务数据多为 Mock，无统一后端与跨端 SSO」

【第 0 层 · 外部角色（最上）】
三个角色节点，从左到右：
1）企业访客 / 企业联系人 —— 浏览与了解产品、登录门户
2）外部账号注册体系 —— 企业在外部完成账号注册后进入控制台（演示约定）
3）平台运营人员 —— 使用运营后台做开通、配置、内容与权限管理

【第 1 层 · 三端业务系统（核心，必须最醒目）】
三个并排系统卡片，自左至右：

A. 对外门户（apps/portal）
- 受众：寻求合作的企业访客
- 职责：品牌与产品介绍、帮助中心、联系与法务、模拟登录；登录后跳转到客户控制台
- 能力要点：首页营销与产品介绍；帮助指南与 FAQ；登录入口；跳转企业控制台
- 技术标注（卡片脚注小字）：Next.js 静态导出

B. 客户控制台（apps/customer）
- 受众：已注册 / 已入驻的企业客户
- 职责：入驻申请与门禁、产品操作台、账号与密钥、使用看板
- 能力要点：
  · 入驻申请独立页 /apply（提交、待审可撤回、驳回可重提；未开通前锁定全站）
  · 工作台（已开通产品与用量概览）
  · 版权核验：DCI核验、版权登记信息核验、版权登记证书核验
  · 作品智能辅助审核：内容安全、作品登记查重、疑似侵权
  · 账号中心 / 改密 / API Keys / API 文档 / 帮助中心（顶栏能力）
- 技术标注：Vite React SPA

C. 运营后台（apps/ops）
- 受众：平台运营与管理员
- 职责：客户与开通审核、产品上架、用量统计、门户内容运营、系统权限与接口目录
- 能力要点：
  · 客户账号管理（含入驻申请审核通过/驳回、产品服务配置）
  · 客户账号列表与合同/服务管理
  · 产品上架：版权核验产品、智能辅助审核产品
  · 运营统计：客户使用、产品使用、账号×产品矩阵
  · 门户内容：首页内容、帮助中心、FAQ
  · 系统管理：角色权限、用户、接口服务设置、操作日志
- 技术标注：Vite React SPA

【第 2 层 · 统一产品能力（被控制台使用、被运营配置）】
一个横向「产品能力带」，标题：「六大产品能力（全端统一编码）」
左侧品类「版权核验 verify」含三项：dci DCI核验；info 版权登记信息核验；certificate 版权登记证书核验
右侧品类「智能辅助审核 audit」含三项：safety 内容安全审核；duplicate 作品登记查重；infringement 疑似侵权审核
可另用虚线框标注 workReview 为「作品智能辅助审核」品类总称
箭头：从「运营后台」指向本层（配置/上架）；从本层指向「客户控制台」（企业使用）

【第 3 层 · 工程共享包】
两个浅色卡片并排：
- @ctp/styles：设计令牌与 portal/admin 样式，三端视觉基线
- @ctp/api-catalog：接口目录种子与类型，支撑运营接口设置与客户 API 文档演示
箭头：共享包向上支撑三端应用

【主业务链路（用一条加粗折线或步骤条画在图侧或中部，步骤编号 1～6）】
1 获客：企业在门户了解产品与帮助
2 注册：外部体系完成账号注册
3 入驻：客户在控制台 /apply 提交企业与合同资料（可撤回保留草稿、驳回后重提）
4 开通：运营在后台审核并配置产品额度/参数；通过后控制台解锁
5 使用：企业在控制台进行核验/审核、查看配额、管理密钥
6 运营：运营持续看统计、管内容与权限

【系统间关系箭头（必须画对，避免画成“三端互通数据库”）】
- 门户 → 客户控制台：登录后 URL 跳转（无 SSO/token 交接），用虚线箭头并标注「跳转」
- 运营后台 → 客户控制台：业务上「开通/配置生效」（原型未打通后端），实线箭头标注「开通与配置（目标态）」
- 运营后台 → 门户：内容运营（帮助/FAQ/首页），箭头标注「内容配置（目标态）」
- 外部注册 → 客户控制台：提供登录账号，进入入驻门禁
- 不要画成三端共享一个数据库；在图注标明「当前为前端原型，各端 Mock/本地状态独立」

【信息准确与禁止项】
- 不要写成单体后台；必须是「门户 + 客户控制台 + 运营后台」三端
- 不要把入驻申请画进「账号中心」；入驻是独立 /apply 锁定页
- 不要省略「未开通前全站锁定」这一门禁关系
- 不要发明微服务/中台名称；本图聚焦业务系统与产品能力，不展开虚构后端集群
- 文字必须是简体中文；专有名可保留 portal / customer / ops、产品 code

输出：一张完整、可读、适合打印的架构示意图（16:9 或 3:2）。
```

## 精简版（模型上下文较短时使用）

```text
生成一张中文分层业务架构图（白底扁平线框，无渐变无emoji）：

标题：DCI® 技术服务中心 · 业务架构

上层角色：企业访客｜外部账号注册｜运营人员

中层三端并排（最突出）：
1 门户 portal：产品介绍、帮助、登录，跳转控制台（Next 静态站）
2 客户控制台 customer：/apply 入驻申请（未开通锁定）、工作台、三核验、三审核、账号/Keys（Vite SPA）
3 运营后台 ops：申请审核与开通、客户/产品、统计、门户内容、角色权限与接口目录（Vite SPA）

下层产品带：版权核验 dci/info/certificate；智能审核 safety/duplicate/infringement

最下共享包：@ctp/styles、@ctp/api-catalog

侧边主链路：获客→注册→入驻→开通→使用→运营

关系：门户虚线跳转控制台；运营实线开通/配置控制台与门户内容。
图注：前端原型，无统一后端与 SSO。
```

## 分镜提示（需要多张再拼图时）

### 分镜 A · 总览关系

```text
只画角色层 + 三端系统三张大卡片 + 关键虚实线箭头（跳转/开通/内容），白底扁平中文架构图，标题「系统关系总览」。不要画产品明细列表。
```

### 分镜 B · 入驻与开通闭环

```text
聚焦客户控制台 /apply 与运营后台「客户账号管理/审核」的闭环：提交→待审→撤回草稿保留→驳回重提→审核通过解锁。流程图+系统边界框，中文，扁平线框。
```

### 分镜 C · 产品能力地图

```text
只画六大产品两列：版权核验三件套、智能审核三件套，并标明由运营配置、由控制台使用。中文扁平信息图。
```

## 自检清单（生成后对照）

- [ ] 是否同时出现 **portal / customer / ops** 三端，而不是一个后台  
- [ ] 入驻是否体现为 **独立申请页 + 未开通锁定**，而不是账号中心里的普通表单  
- [ ] 六大产品 code 与中文名是否齐全  
- [ ] 门户→控制台是否标成 **跳转（非 SSO）**  
- [ ] 是否注明 **原型 / Mock、无统一后端**（避免被当成已上线全链路）  
- [ ] 共享包是否仅为 styles + api-catalog，未虚构多余中台

# 05 API 约定

## 版本与前缀

| 前缀 | 说明 |
|------|------|
| `/api/v1` | 门户登录 + 客户平台 + 运营后台 |
| `/open/v1/{productCode}` | 可售同步 API |

运营专用路径挂在 `/api/v1/ops/...`，客户专用 `/api/v1/me/...` 或 `/api/v1/console/...`。不要把运营接口与客户接口混在同一 Controller 后靠注释区分。

## 统一响应（管理面）

成功：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "requestId": "01J..."
}
```

失败：`code != 0`，`data` 可空，`message` 给人看。HTTP 状态仍按语义设置（401/403/404/409/422/429/500）。

## 开放 API 响应

在统一结构上增加用量（字段名实现时保持稳定）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "requestId": "01J...",
  "usage": {
    "billed": true,
    "remaining": 1234
  }
}
```

未计费时 `billed: false`，并在 `message` 或约定错误码说明原因（额度不足、上游失败等）。

## 错误码（稳定，业务依赖）

| code | 含义 |
|------|------|
| 0 | 成功 |
| 40101 | 未登录 / Token 无效 |
| 40102 | API Key 无效或已吊销 |
| 40301 | 企业不可访问运营接口（或相反） |
| 40302 | 租户未开通该产品 |
| 40303 | 租户停用 |
| 40901 | 幂等键冲突且原请求未完成（若采用） |
| 42201 | 参数校验失败 |
| 42901 | 限流 |
| 40201 | 额度不足 |
| 50401 | 上游超时 |
| 50201 | 上游失败 |
| 50000 | 未分类内部错误 |

产品业务错误放在 `data` 或使用 `42xxx` 段，在该产品文档中声明。

## 幂等

所有会产生扣次的请求：

- 开放 API：请求头 `Idempotency-Key`（客户传入）或网关对「相同 Key + 相同指纹」去重。
- WebUI：由服务端为该次提交生成并写入日志，前端禁止重复连点；仍建议带客户端 `Idempotency-Key`。

同一 `Idempotency-Key` 重放：返回**第一次**的成功结果或进行中/失败状态，不得二次扣费。

## 开放 API 鉴权

请求头：`Authorization: Bearer <apiKey>` 或 `X-API-Key: <apiKey>`（实现选定一种，文档写死一种）。

Key 明文只在创建时返回一次。

## 文档

OpenAPI 3 为接口真相。客户平台「API 文档」页渲染同一 spec 的过滤视图（仅该租户已开通产品）。不要手写第二份与代码漂移的 Markdown 接口说明作为真相源。

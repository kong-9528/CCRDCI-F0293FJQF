# 文档使用方法
## 本文定义
这是一份经过长期经验总结的标准产品需求说明书的行文规范，主要目的是正式地明确了在撰写产品需求说明书时，每面对一个页面、一个板块、一个组件、一个元素、一个交互、某种类型的业务内在逻辑、以及某个类型的业务流程时，我们应该从哪些方面进行描述和说明，以求非常完整地讲述好需求。

## 有待补充和完善
尽管如此，这份文档中仍然会有一些尚未覆盖到的场景、组件、元素、交互、以及业务逻辑和业务流程。

## 遵循准则
对于本文已经明确的“页面、板块、组件、元素、交互、业务逻辑、业务流程”等等items，以及本文已经明确的“具体需求点的描述内容”，请严格遵循本文的规则去撰写产品需求说明书。对于本文尚未提及的items，请认真地、全面地分析该item的特点，以及该item在整个项目中的业务规则，然后尽可能规范地、全面地进行需求描述。

## 需要描述的items的定义
本文将需要描述的产品items划分为以下几类：



| 章节主题 | 声明了什么样的需求描述规范 |
| --- | --- |
| List Item | 规定了关于“列表页 / 一个列表板块 / 一个简单的清单list”中常见的、需要描述的需求点。 |
| Detail Item | 规定了关于“详情页 / 详情展示的板块 / 直接展示的字段”中常见的、需要描述的需求点。 |
| Form Item | 规定了关于“提交表单页 / 提交表单的板块 / 要直接提交的字段”中常见的、需要描述的需求点。 |
| Preview Layer Item | 代表查看大图的浮层，但其中可以包含多种多媒体格式，例如“图片、视频、VR、全景格式”等等可以实现全屏预览的格式。 |
| The Rest Item | 代表不是明确归属于一个“页面、板块、组件、元素、交互、业务逻辑、业务流程”中特有的细节需求点；<br/>或者代表这个细节需求点可以在多个Item类型中都可能存在这个需求点；<br/>就可以从这个章节中寻找遵循规范。 |


# List Item
## 数据描述
### 数据来源
+ 用于描述要展示的数据源是从哪里来的（例如合同列表/用户列表这种就可以不用提，待审核列表需要介绍是谁提交了什么信息，对于统计报表需要描述列表里的数据是基于哪个报表或哪些报表来做的统计）

### 数据范围
+ 用于描述当前登录用户能够查看什么范围内的数据，可能跟用户的权限相关，也可能跟用户的组织架构相关，也可能跟用户当前付费状态等场景相关。

### 数据的状态迁移
+ 对于审核类/合同类/收款类/订单类的列表页，还需要综合描述业务数据的状态迁移内在逻辑，可以是状态迁移图，也可以是业务流程图，要描述清楚“哪类用户”在“哪个平台”对“什么数据”去做“什么操作”，可以完成“哪一个状态转移”

## 排序规则
+ 用于描述列表中的记录按照什么样的规则排序
+ 可以是按单一条件，也可以是按多个条件但要有优先级，如“优先按XX正序/倒序，同等条件下按YY正序/倒序，同等条件下按ZZ正序/倒序”

## 筛选项
### 是否有筛选项
+ 如果有筛选项，则用于描述可以通过哪些筛选项目进行搜索，搜哪个字段，精准搜还是模糊搜

### 常见组件-输入框
+ 描述字段名称
+ 默认是否为空，为空时的placeholder文案
+ 是否限制输入的字符类型（例如是任意字符，或者是只能输入数字或数值，等等）
+ 搜哪个或哪些字段，精准搜还是模糊搜

### 常见组件-下拉单选/平铺单选
+ 描述字段名称
+ 默认“为空”还是“默认就选中选项清单中的某一个选项”，为空时的placeholder文案（例如请选择xxx），为空代表搜全部
+ 可选选项有“全部，<后面具体罗列每个选项>”，具体的选项是否要以某个数据字典为准
+ 搜的是哪个字段
+ 对于下拉方式的交互是否需要支持输入关键词从选项中模糊匹配
+ 多个下拉框之间是否有联动关系（例如A字段选择具体选项后，B字段才有二级选项可选择，相当于B字段是A字段的二级字段；例如联动方式是“始终展示A和B，但不选A就无法选B”，或者“在A未选择任何选项时，隐藏B”，等等）

### 常见组件-下拉多选/平铺多选
+ 描述字段名称
+ 默认是否为空，为空时的placeholder文案（例如请选择xxx），为空代表搜全部
+ 可选选项有“全部，<后面具体罗列每个选项>”，具体的选项是否要以某个数据字典为准
+ 搜的是哪个字段
+ 对于下拉方式的交互是否需要支持输入关键词从选项中模糊匹配

### 常见组件-带有层级的组织架构的下拉单选/多选
+ 描述字段名称
+ 默认“为空”还是“默认就选中选项清单中的某一个选项”，为空时的placeholder文案（例如请选择xxx），为空代表搜全部
+ 可选的选项需要按组织架构层级关系罗列
+ 可选的选项的范围是什么样的
+ 支持展开收起
+ 搜的是哪个字段

### 常见组件-时间段
+ 描述字段名称
+ 默认是否为空（还是必须选择一个时间范围例如默认昨天到昨天、默认今天到今天、默认近7天的日期范围、或者默认近30天的日期范围，等等）
+ 是否允许搜全部（如果可以，可将空代表搜全部）
+ 起止都是日期格式（不需要时分秒）
+ 搜的时候包含开始日期和结束日期的当天，开始不能晚于结束
+ 对开始时间最早/结束时间最晚是否有要求
+ 对时间跨度是否有要求

### 常见组件-数值范围
+ 描述字段名称
+ 默认是否为空，为空时的placeholder文案（或者可以没有文案），为空代表搜全部
+ 搜的是哪个字段
+ 对于左输入框为空或右输入框为空时代表搜<=或>=
+ 搜的时候包含左输入框的值和右输入框的值
+ 左输入框不能大于右输入框

## 列表字段
### 逐一描述每个字段
#### 常见字段
+ id类
+ 城市名称类
+ 只有的文本类（例如合同编号，备注、姓名等等可以在录入时自由输入的内容）
+ 普通的数据字典表中的业务定义（例如属于哪一类合同，哪一类数据，哪一类业务，等等）
+ 日期类（只展示到年月日）
+ 时间戳类（例如年月日时分秒）
+ 人员类（例如记录的业务负责人、归属人、操作人、最后更新人员、等等）
+ 人员所在架构（一般只展示直接所属的架构节点名称）
+ 金额类（例如金额的单位，精确到分，等等描述）
+ 数值类（例如统计的数量，特殊情况要展示0还是展示“-”，等等）

#### 每个字段还需要说明
+ 取这条记录表或该记录的关联表的哪个字段（以及计算规则，尤其是在统计相关的列表中要描述一个指标的具体定义，有时还需要定义计算方法）
+ 显示时是否需要对不同的值有不同的字色显示
+ 是否需要有点击效果（例如点击打开一个浮层查看大图，打开一个抽屉查看详情，打开一个新页面链接到哪里，打开一个弹窗以提交某个表单，打开一个弹窗以下钻查看更详细的明细，等等）

## 翻页
下面列出了常见的翻页组件的需求描述点：

### 是否需要翻页
+ 一般列表板块需要翻页
+ 但对于“下载记录/近x天的记录”等可能存在定期删除的情况，以及对于“组织架构”这样带有层级结构的板块，以及对于“角色/权限清单”这样的有限数据或需要一览无余的数据，可以不要翻页

### 翻页组件的位置
+ 是否上下都要有，还是只需要在下方；

### 组件本身描述
+ 左侧显示“共 X 条”总数
+ 右侧为页码翻页组（上一页、数字页码、下一页）
+ 是否支持输入页码直接跳转到某页
+ 是否需要首页、尾页，默认第1页，当前页高亮
+ 每页条数默认10条，可选择每页条数为“10条，20条，50条，100条”

## 单条记录操作
### 新增/修改类操作
+ 是基于本条记录来新增/修改某个业务内容，一般是打开一个弹窗/抽屉、跳转到哪里、或者是在按钮处展开一个选项清单来选择要做什么操作，可能需要配合指向到其他某个章节的页面或弹窗需求里，这类操作一般是要基于这条记录来提交某种业务的表单

### 审核/核查类操作
+ 一般是打开一个弹窗、浮层、抽屉、或页面，其中包含一部分“详情展示”的板块，也包含一部分“提交表单”的板块（用来提交审核或核查的结果，这时经常会对不同的审核结果有不同的额外字段参与联动，例如通过的时候可以做什么操作，拒绝的时候做什么操作）

### 移除/删除/启用/禁用停用/废弃类操作
+ 一般这类操作需要一个二次确认提示框，以向用户说明该操作在业务中是什么作用，有什么风险

## 全局操作
### 新增、上传等等类型的操作按钮
描述什么样的用户有此权限，点击后打开或弹出什么样的交互来进行下一步（例如跳转到哪里，或打开弹窗，或打开抽屉，等等）

### 多选操作
是否支持多选、全选本页、全选全部搜索结果，如支持多选则翻页时是抛弃上一页所选还是记录下上一页所选（以及如何通过交互向用户明确表达这个内在逻辑）

## 对上述字段和操作，还可能需要描述的需求点包括
+ 如果发生异常，需要有异常提示的定义，例如：有联动关系的筛选项组件，用户发生非正常的操作时，需要提示引导用户应该先选择什么，再选择什么

# Detail Item
## 详情板块主要描述具体的字段约束和呈现逻辑
#### 常见字段-文本
+ 描述字段名称
+ 展示格式（例如单行文本、多行文本超出自动折行、超出是否截断）
+ 是否需要有字色的特殊要求

### 常见字段-单选类的值
+ 描述字段名称
+ 展示格式（例如展示成纯文本、label标签）
+ 是否需要有字色或填充色的区分
+ 场景例如“状态/业务中的字典表的选项值”

### 常见字段-多选类的值
+ 描述字段名称
+ 展示格式（例如展示成纯文本并且用逗号隔开、展示成多个label标签平铺）
+ 展示不下时是否折行必须展示全部选项、还是允许默认收起并且点击展开时再可查看全部选项
+ 是否需要有字色或填充色的区分
+ 场景例如“业务中的字典表的选项值”

### 常见字段-时间
+ 描述字段名称
+ 展示格式（年与日格式、年月日时分秒格式、年月日时分格式、等等）
+ 是否需要有字色的特殊要求

### 常见字段-时间段
+ 描述字段名称
+ 展示格式（例如“yyyy-mm-dd 至 yyyy-mm-dd”，等等）
+ 是否需要有字色的特殊要求

### 常见字段-金额
+ 描述字段名称
+ 展示格式（例如展示的金额单位，精确到分）
+ 是否需要有字色的特殊要求

### 常见字段-数值/数字
+ 描述字段名称
+ 展示格式（例如展示统计的量、额度、面积、百分比、等等概念，是否支持小数点、精确到几位、等等约束）
+ 是否需要有字色的特殊要求

### 常见字段-图片等可预览的文件
+ 描述字段名称
+ 展示格式（例如正方形预览、长方形预览、等等，加载中的样子、链接失效的样子、加载成功的样子、等等，图片在缩略图框体里撑满框体的策略）
+ 对预览框是否有一些操作（例如移除，查看，替换为新图，给图片打标签/设置类别，等等）

### 常见字段-普通的附件
+ 描述字段名称
+ 展示格式（例如每个附件展示成某种形状的框体或者是label形式）
+ 点击下载的交互方式

### 常见字段-label标签/标记/提醒类的字段
+ 描述字段名称
+ 展示位置（例如用来对哪个字段进行“标记/预警/提醒”，以及满足什么样的条件和内在逻辑时要展示出来）
+ 展示的具体内容的内在业务逻辑
+ 展示格式（例如展示成纯文本、label标签）
+ 是否需要有字色或填充色的区分

## 一个详情板块中也可能藏有操作
### 可能是全局操作
+ 意思是一个按钮可以对详情所代表的这条记录进行一个操作，可能会与“列表中的单条操作”一致

### 可能是一个跳转入口
+ 意思是，点击打开弹窗/其他页面等等

### 可能是一个局部操作
+ 意思是展示在某个字段的旁边，操作时仅仅针对这个字段进行操作（例如“修改一个状态字段的值、或者“修改这条记录归属的人员、公司等等”）

### 这些操作都可能涉及到权限
+ 例如，面向哪些用户或符合什么条件的用户展示这个操作入口

## 根据实际情况，上述每类“字段或者操作”还可能需要描述的需求点包括
+ 字段信息从哪里获取
+ 可能有哪些状态或取值范围，不同种状态或情况背后对应了怎样的业务逻辑，应该如何展示
+ 是否要有颜色等区分，是否需要“醒目强化或配色弱化”
+ 是否需要面向部分用户隐藏不可见：例如正处于某个审核节点时会有一些核心字段不能展示给当前审核节点的人员去查看，等等
+ 字段的值为空时如何展示或呈现（例如为空时隐藏该字段并且其余字段自动上移补位、为空时不展示任何值、为空时展示“暂无”/"-"，等等
+ 是否需要支持点击：例如点击统计数字可下钻查看具体数值对应的明细，或者点击一个坐标查看地理位置，或者点击缩略图进入一个浮层（如大图模式或视频播放模式），等等

# Form Item
## 提交表单的板块主要描述具体的字段约束和呈现逻辑
### 常见组件-输入框
+ 描述字段名称
+ 数据格式（例如单行文本、多行文本）
+ 是否必填
+ 默认“为空”还是“自动带入业务中的某个字段的值”（如果是自动带入的情况下，带入后是否可修改），为空时的placeholder文案
+ 是否限制输入的字符类型（例如是任意字符，或者是只能输入数字或数值，等等）
+ 限制的最大字数上限
+ 超出字数时输入无效
+ 是否在输入框旁边实时显示已输入字数
+ 对输入内容有什么业务上的要求（例如一行一个手机号的要求，例如必须符合邮箱格式/手机号格式/本业务约定的验证码格式，等等）

### 常见组件-下拉单选/平铺单选
+ 描述字段名称
+ 是否必填
+ 默认“为空”还是“默认就选中选项清单中的某一个选项”，为空时的placeholder文案（例如请选择xxx）
+ 为空代表搜全部
+ 可选选项需要具体罗列每个选项以明确需求，具体的选项也可以是以某个数据字典为准
+ 下拉选项有时也可以展示多个信息（例如每个选项在样式上可以区分出主要信息、次要信息以更好地辅助说明这个选项）
+ 下拉选项有时也可以是只有部分选项可选择（例如选项之间是排他的，所以部分选项在之前已经选过了，本次只能选择其余选项）
+ 对于下拉方式的交互是否需要支持输入关键词从选项中模糊匹配，多个下拉框之间是否有联动关系（例如A字段选择具体选项后，B字段才有二级选项可选择，相当于B字段是A字段的二级字段；例如联动方式是“始终展示A和B，但不选A就无法选B”，或者“在A未选择任何选项时，隐藏B”，等等）

### 常见组件-下拉多选/平铺多选
+ 描述字段名称
+ 是否必填
+ 默认是否为空，为空时的placeholder文案（例如请选择xxx）
+ 可选选项需要具体罗列每个选项以明确需求，具体的选项也可以是以某个数据字典为准
+ 对于下拉方式的交互是否需要支持输入关键词从选项中模糊匹配

### 常见组件-带有层级的组织架构的下拉单选/多选
+ 描述字段名称
+ 是否必填
+ 默认“为空”还是“默认就选中选项清单中的某一个选项”，为空时的placeholder文案（例如请选择xxx）
+ 可选的选项需要按组织架构层级关系罗列
+ 可选的选项的范围是什么样的
+ 支持展开收起

### 常见字段-时间
+ 描述字段名称
+ 是否必填
+ 展示格式（年与日格式、年月日时分格式、等等）

### 常见组件-时间段
+ 描述字段名称
+ 是否必填
+ 默认是否为空（还是必须选择一个时间范围例如默认昨天到昨天、默认今天到今天、默认近7天的日期范围、或者默认近30天的日期范围，等等）
+ 格式（例如“yyyy-mm-dd 至 yyyy-mm-dd”，等等）
+ 起止都是日期格式（不需要时分秒）
+ 时间的定义包含开始日期和结束日期的当天
+ 开始不能晚于结束
+ 对开始时间最早/结束时间最晚是否有要求
+ 对时间跨度是否有要求

### 常见组件-数值范围
+ 描述字段名称
+ 是否必填
+ 默认是否为空，为空时的placeholder文案（或者可以没有文案）
+ 是否允许左输入框为空或右输入框为空
+ 左输入框不能大于右输入框

### 常见字段-金额
+ 描述字段名称
+ 是否必填
+ 格式（例如展示的金额单位，精确到分）
+ 最小和最大值约束
+ 有时候还需要考虑金额是否不允许输入，而是通过其他几个字段自动计算出一个预览的数值

### 常见字段-数值/数字
+ 描述字段名称
+ 是否必填
+ 格式（例如展示统计的量、额度、面积、百分比、等等概念，是否支持小数点、精确到几位、等等约束）
+ 最小和最大值约束
+ 有时候还需要考虑数字/数值字段是否不允许输入，而是通过其他几个字段自动计算出一个预览的值

### 常见字段-图片等可预览的文件
+ 描述字段名称
+ 是否必填，格式（例如正方形预览、长方形预览、等等，例如上传中的样子、上传失败的样子、上传成功的样子、等等；例如图片在缩略图框体里撑满框体的策略）
+ 上传的操作
+ 对预览框是否有一些操作（例如移除，查看，替换为新图，给图片打标签/设置类别，等等）
+ 是否需要支持对图片拖动排序

### 常见字段-普通的附件
+ 描述字段名称
+ 是否必填
+ 展示格式（例如每个附件展示成某种形状的框体或者是label形式）
+ 上传的操作
+ 点击下载的交互方式
+ 是否需要支持对图片拖动排序

### 常见字段-label标签/标记/提醒类的字段
+ 描述字段名称
+ 展示位置（例如用来对哪个字段进行“标记/预警/提醒”，以及满足什么样的条件和内在逻辑时要展示出来）
+ 展示格式（例如展示成纯文本、label标签）
+ 是否需要有字色或填充色的区分

### 常见组件-滑块交互方式
+ 数量、数值、等级等等类型的字段：也可能会设计成滑块类的交互设计，方便用户快速拖动以得到想要的值

### 常见组件-拖动排序交互方式
+ 有时在提交的表单中包含了一部分“整齐的列表”形式的表单内容（例如多个公司记录，多个产品记录，多张图片，多个附件，等等），此时有可能支持拖动排序的交互，此时前端要明确记录最终的排序顺序（即用户可见的顺序），并将这个顺序准确地提交给后端

## 常见的操作
### 提交类/保存类操作
+ 需要描述这个提交的正常逻辑是要做什么业务上的处理（例如是保存为草稿，还是正式提交并创建一个什么记录，记录提交后处于什么样的状态，下一步可以或者应当由什么身份的用户来继续操作/管理它，等等）
+ 提交时前端校验什么
+ 交给后端之后由后端校验什么
+ 对于各类异常要如何提示去引导用户/警告用户

### 取消类操作
+ 是否二次确认以提示用户谨慎操作（因为用户离开该提交表单的页面或板块后会导致修改过的内容被抛弃），避免用户不小心点击取消不符合用户本意。

## 根据实际情况，上述每类“字段”还可能需要描述的需求点包括
+ 是否自动带入业务中的某个字段的值（例如在一个节点上点击新增，那么新增表单中的所属上级节点应该有默认自动带入值）
+ 不符合约束时需要“实时的字提示”，还是“失去焦点时判断”，还是“点击提交时统一判断”

# Preview Layer Item
## 查看大图模式下，主要是浏览状态的浮层，需求点需要包括
+ 可能出现的文件格式有哪些：例如图片、视频、VR、全景格式、等等
+ 内容之间是否要定时自动切换下一个，还是必须手动点击才能切换
+ 首尾是否循环切换
+ 图片的格式是否支持鼠标滚轮放大缩小，是否支持在浮层内上下左右拖动图片
+ 浮层内是否要展示图片数量的标记（例如：1/12）
+ 浮层内是否要展示所有多媒体文件的缩略图，并且是否支持直接点击缩略图到第几个多媒体文件
+ 如果是视频类的文件，每次切换到视频类的文件后，都是自动播放，还是都需要手动点击播放按钮，是否支持拖动进度条，音量调节，下载视频，等等操作
+ 如何关闭浮层：点击叉号关闭按钮才关闭

## 在大图模式下，也有一些异常场景需要定义
+ 某多媒体文件加载失败或者链接坏掉，页面上该如何处理，该如何提示

# The Rest Item
## 辅助说明性的文字
+ 一般可以是“走马灯形式/字段输入框下方或右侧的位置用小灰字/字段的值的下方或右侧的位置用小灰字/在一个板块的标题的右侧或下方的小灰字”

## 小问号/小叹号/小info图标
+ 一般是通过“点击/鼠标悬浮”等方式，打开“小气泡/浮层/弹窗”等形式，来呈现“说明/声明/指标解释/操作指引”等内容

## 查看详情/查看更多的文字链
+ 一般是放在一个板块的标题所在行居右展示，或者是放在某个字段的值的旁边以引导用户点击，点击后会链接到更多的信息或新的页面/弹窗抽屉等等形式

## 涉及到点击一个操作按钮，在当前页面打开其他页面的交互
+ 一般我们需要定义一下是否需要返回，返回时回到哪里。尤其是涉及到这个目标页面可以从多个入口链接访问到的情况
